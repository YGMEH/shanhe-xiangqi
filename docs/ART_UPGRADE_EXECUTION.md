### 0.2 版本与预览安全规则

1. 在用户明确说“允许切换版本 / 可以 rebuild / 可以覆盖预览”之前：
   - 不执行 `npm.cmd run build`。
   - 不覆盖 `dist`。
   - 不替换 `public/assets` 中正在运行的贴图或 GLB。
   - 不启动新的替代预览服务器来冒充 4173。
2. 所有新资源先放在 `work/` 或 `tmp/` 隔离目录；旧资源、生成图、视频、音频和用户下载的 GLB 一律保留。
3. 代码修改前先读取目标文件；不要用整文件覆盖去“整理格式”，只做最小范围编辑。
4. 每个阶段都必须能独立回退：阶段失败时只撤销该阶段的文件，不碰其他 agent 或用户的改动。
5. 任何截图先写入 `work/shots/`；需要用户通过 HTTP 查看时，再复制成新的 `public/shots/<唯一名称>.png`，不能覆盖已有截图，也不能删除历史截图。
6. 所有资源检查必须同时验证 HTTP 状态码和 `Content-Type`，防止 SPA 回退把 `index.html` 误当图片或模型。

- PowerShell 中使用 `npm.cmd`、`npx.cmd`，不要使用会被执行策略拦截的裸 `npm`/`npx`。

- 真实场景截图以 `work/capture_preview_current.py` 为模板，必须先点击 `#start-button`，等待 `window.__SHANHE_DEBUG__?.scene` 和 `controller`，再截图。
- GPU 无硬件时使用 Playwright 参数：`--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`。

## 1. 给低成本模型的总执行协议

低成本模型每轮只处理一个任务包，不允许“顺手”改动下一阶段内容。每轮开始和结束都要输出以下结构：

```text
任务 ID：AU-xx
目标：
本轮允许修改：
本轮禁止修改：
输入证据：
实施文件：
验证命令与结果：
截图/报告路径：
风险与未完成项：
是否达到阶段门：是/否
```

模型必须遵守：

- 先读 `docs/ART_BRIEF.md` 和本文件相关章节，再读目标源码。
- 先写验证脚本或报告，再做资源替换；不能用主观截图取代指标。
- 失败时保留失败产物和错误报告，不删除以往候选。
- 看到预览约束时，将任务降级为“隔离候选 + A/B”，不得自行 rebuild。
- 不把 Inspect、压缩产物或缓存文件当作源代码修改证据。
- 每次只允许一个主题变更：材质、环境、地表、营地、棋子、UI 不得混在同一个提交/批次。

## 4. 阶段 1：材质层（AU-10～AU-12）

### 核心决策

全套 2K 已经 A/B 证明性价比不足，所以材质优化从“放大分辨率”改为“只提升画面真正暴露的频段”：

1. 保持当前 1024 WebP 作为基线。
2. 优先研究 sandstone/rock 的混合方案，而不是同时替换 stone 和 wood。
3. 优先候选：1024 颜色 + 1024 法线，加入低成本局部高频（程序化 detail normal/detail color）；或者只给近景明显可见的棋盘区域使用局部贴图。
4. 候选必须证明在放大镜头中更清晰，而不是只让像素差变大。

### AU-10：候选编码与预算

- 输入：`work/polyhaven-cache/rock_ground_02_*_2k.jpg`、当前 sandstone 贴图。
- 输出：`work/texture-hybrid-candidate/<variant>/`、`report.json`。
- 预算：sandstone 三张新增总量原则上不超过当前三张总量的 1.5 倍；全套资源预算不超过当前 2,678,900 B 的 1.35 倍，除非报告说明收益来自可见近景区域。
- 报告必须记录：尺寸、字节、WebP 参数、PSNR/SSIM（若可算）、边缘连续性、平铺接缝差、加载失败数。

### AU-11：浏览器隔离 A/B

- 使用 request interception，不改 `public`、`dist`、源代码。
- 至少采集默认视角、放大 5 档、低机位三个镜头。
- 每个镜头记录：截图路径、资源 transferSize、console error、HTTP 失败、画布尺寸、A/B 像素差。
- 验收不是“差异越大越好”：必须由截图确认纹理细节提升且没有新噪点、重复纹理、色调漂移或棋子可读性下降。

### AU-12：决定是否集成

- 若混合候选没有明确视觉收益：保留候选和报告，结论为“不集成”。
- 若有明确收益：只提出最小替换清单，等待用户授权切换版本；在授权前不复制到 `public`。
- 不允许以“2K”作为集成理由，必须写出“哪一个镜头、哪一种表面、哪一项可见收益”。

## 5. 阶段 2：天空、远景、地表（AU-20～AU-23）

### AU-20：环境一致性

检查 `src/render/scene.js` 中：

- `scene.background`、程序化 sky dome、`scene.fog`、远山顶点色、sun/rim/warmFill 的色温是否一致。
- `public/assets/art/valley-backdrop.webp` 是否确实为 2:1、水平接缝是否通过 `tmp/fix_seam3.py` 指标。
- 远景不能只靠提高饱和度解决；优先调整层次、雾、轮廓和地平线过渡。

验收：默认、低机位、顶部视角各一张，地平线无冷暖硬切，远山不抢棋子主体。

### AU-21：棋盘与河流

- 保持 `LINE_LIFT = 0.006` 和 polygon offset 的已验证方案，不要回到线宽等于抬升量。
- 保持河床卵石破水线方案：卵石 y 在约 `-0.10` 到 `+0.09`，不要再次只调暗水下石头颜色。
- 优先检查水面、泡沫、桥脚接触、阴影和 z-fighting。

### AU-22：边界叙事

- 检查远山、树、帐篷、旗帜、拒马是否遮挡前排棋子和镜头通视带。
- 不增加无意义的高密度小物件；每个新增物件必须强化“战场/两军营地/河谷”中的一个叙事信息。

### AU-23：视觉报告

生成 `work/shots/AU-2x-*.png` 和 `work/reports/AU-2x-report.json`。报告至少有遮挡检查、地平线检查、河流接触检查和 draw call/三角面粗略记录。

## 6. 阶段 3：几何小物件与营地（AU-30～AU-34）

### 原则

- 先修轮廓，再修材质；“颜色调得更暖”不能替代错误的几何比例。
- 近景可见物件使用少量倒角、非均匀缩放、法线和阴影；远景物件保持低面数。
- 不把通用 treasure chest GLB 误当作 chariot；它是静态合并网格，适合作为营地储物道具，是否采用需单独验证。

### 任务

- AU-30：军帐与拒马轮廓，保持四面攒尖、贴墙檐口、宝顶旗杆的已验证比例。
- AU-31：桥梁石构件、望柱头、石狮；重点检查接地和阴影。
- AU-32：河床卵石、泡沫和岸边贴地草斑；严禁恢复竖直“黑刺草”。
- AU-33：两军营地的层次、旗帜和通视带；任何新增帐篷先做遮挡回归。
- AU-34：只在有叙事价值时增加武器架、柴堆、火盆、粮车等；每类先做 1 个原型，不得批量铺满。

每包输出一个独立截图和一份变更清单；失败原型留在 `work/`，不删除。

## 7. 阶段 4：棋子模型、尺寸与动画（AU-40～AU-44）

### 已知资源结论

- 古炮 GLB：静态，无骨骼/动画/形态；只允许整体待机、俯仰和后坐，不要声称有真实炮管骨骼。
- 战象 GLB：31 joints，约 2.6 秒 walk clip；先验证动画落地、循环和程序化回退。
- 当前骑兵改用 mounted-warrior 静态骑手模型，无骨骼/动画；保留原 horse-armored 作历史候选，不假设存在 clip。
- treasure chest：静态合并网格，无 lid/wheel/hinge；仅作为营地储物物件候选。

### 任务

- AU-40：模型 manifest 和加载失败回退；每个模型错误不能让 Promise 永不 settle。
- AU-41：模型尺寸、贴地、阵营朝向、底座压平；验收不能只看 bounding box，要验证真实 SkinnedMesh 顶点落地。
- AU-42：战象 walk clip；检查动画名称匹配、循环次数、移动结束回到 idle。
- AU-43：无动画骑兵与静态古炮；保留整体程序化动作和炮击后坐，不覆盖旧模型文件。
- AU-44：棋子 A/B 截图和轻量性能检查；检查 32 枚棋子加载、首帧、draw call、显存风险和移动/吃子/悔棋。

验收必须覆盖：红黑双方、默认视角、近景、移动、攻击、吃子、悔棋、模型加载失败时的程序化棋子。

## 8. 阶段 5：UI 质感和可读性（AU-50～AU-52）

### AU-50：首屏与对局 UI

- 保持 `src/styles.css` 的古铜、朱砂、青黑主色；优先调整层级、留白、对比度和小屏布局，不用大面积亮纹理。
- UI 背景图必须走 `src/assets/art/` 的 Vite 管线，不能使用根绝对路径。
- 保持开始按钮、双方信息、回合提示和底部操作栏在 1440×900、1366×768、390×844 可读。

### AU-51：交互状态

检查 hover、selected、disabled、结果面板、音效静音、相机工具和 reduced-motion；不能只拍静态首屏。

### AU-52：回归截图

输出三种分辨率、开始界面和对局界面截图；报告记录文字溢出、遮挡、对比度、点击目标尺寸和控制台错误。

## 9. AU-90：用户授权后的切换与发布

只有用户明确允许切换版本后才能执行：

1. 先创建人工快照：`undo_snapshot`，备注写明待切换的 AU 任务 ID。
2. 运行 `npm.cmd test` 和 `npm.cmd run check:public`。
3. 先构建隔离目录，例如 `npx.cmd vite build --outDir dist-candidate-au90`，检查产物和资源 MIME；不要一上来覆盖 `dist`。
4. 在用户批准的候选预览地址验证默认/低机位/顶部/移动/攻击五类场景。
5. 只有候选通过性能、视觉、功能三道门，且用户再次确认“切换”，才执行正式 `npm.cmd run build`。
6. 正式构建后验证 `http://127.0.0.1:4173/`；若预览服务器仍指向旧进程，不能声称 4173 已更新。
7. 任何失败优先用 `undo_restore` 回到最近良好快照，不手工猜测配置。

### 发布三道门

- 视觉门：关键镜头确有改善，不能只是像素差变大。
- 功能门：测试通过，加载失败有回退，无 console/page error，移动/攻击/吃子/悔棋可用。
- 性能门：资源预算、首屏加载、draw call、三角面和截图帧率没有超出报告中的基线容差。

## 10. 推荐给低成本模型的第一批实际任务

切换到便宜模型后，不要让它直接“继续美化”。第一轮只执行：

1. `AU-00`：生成基线报告，不改运行资源。

4. `AU-23`：用现有源码和截图建立“遮挡/地平线/接地”检查表。

完成以上四项后，再按 AU-20 → AU-30 → AU-42 → AU-50 的顺序推进。材质 2K 不再作为默认第一工程；只有 AU-11 证明混合方案可见收益时才重新进入集成候选。
